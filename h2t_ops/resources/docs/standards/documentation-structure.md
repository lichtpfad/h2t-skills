# Documentation Structure

Per-repo `docs/` layout standard for the H2T platform. Applies to all `h2t-*` repositories.

## Required Core Directories

Must exist in every repo:

```
docs/
├── README.md                              # Index/navigation for this repo's docs
├── superpowers/                           # AUTO-GENERATED by Superpowers skills
│   ├── specs/                             # YYYY-MM-DD-feature-design.md
│   └── plans/                             # YYYY-MM-DD-feature.md
├── adr/                                   # Architectural Decision Records
│   ├── NNNN-decision-name.md              # MADR format
│   └── index.md                           # Auto-generated list
└── reports/                               # Milestone/phase reports
    └── mN-report-name.md
```

## Conditional Directories

Create only when applicable. The flag source is `projects.yaml` per repo.

```
├── product/                               # When projects.yaml.docs.positioning = true
│   ├── positioning.md
│   ├── mvp-scope.md
│   └── eval-report.md
│
├── client/                                # When repo exposes a public API
│   ├── README.md                          # Entry point
│   ├── quickstart.md
│   ├── api-guide.md                       # Links to api/openapi.yaml (if exists)
│   ├── examples/
│   └── faq.md
│
├── marketing/                             # When projects.yaml.docs.marketing_docs = true
│   ├── positioning.md
│   ├── use-cases.md
│   └── case-studies/
│
├── architecture/                          # When repo has complex internal architecture
│   ├── system-design.md
│   ├── data-flow.md
│   └── components.md
│
├── guides/                                # When repo has external users or onboarding needs
│   ├── getting-started.md
│   ├── best-practices.md
│   └── troubleshooting.md
│
├── research/                              # When exploratory work exists
│   └── YYYY-MM-DD-topic.md
│
└── .artifacts/                            # When repo generates temp operational data
    ├── logs/
    ├── operational/
    └── test-results/
```

### projects.yaml Flag Mapping

| projects.yaml flag | Conditional directory |
| --- | --- |
| `docs.positioning = true` | `docs/product/` |
| `docs.marketing_docs = true` | `docs/marketing/` |
| `docs.agent_docs = true` | `docs/client/` |
| `docs.eval_report = true` | `docs/reports/eval-report.md` (specific file) |
| repo has `api/openapi.yaml` | `docs/client/api-guide.md` |

## Repo-Specific Extensions

Repos MAY have additional directories in `docs/` for domain-specific content.

| Repo | Extension | Purpose |
| --- | --- | --- |
| h2t-ai | `context7-cache/` | Cached code patterns |
| h2t-ai | `eval/` | Eval contracts, prompts, sessions |
| h2t-ai | `registry/` | Operator registries (reference data) |
| h2t-ai | `handoff/` | Session handoff snapshots |
| h2t-evals | `ops/` | Operational runbooks, evidence |
| h2t-evals | `contracts/` | LLM judge contracts |
| h2t-transcription | `methodology/` | Course spec templates |
| h2t-transcription | `diagrams/` | Pipeline diagrams |
| h2t-vision | `presentation/` | Presentation materials |

**Rules for extensions:**
- Directory name: lowercase kebab-case
- Must have a README.md explaining purpose
- Must be documented in repo's `docs/README.md` navigation
- JSON/data-heavy dirs should move to `src/` or `data/` when >80% non-markdown

## Directory Descriptions

| Directory | Purpose | Audience | Lifecycle |
| --- | --- | --- | --- |
| `superpowers/` | Auto-generated specs and plans from Superpowers skills | Developers, AI agents | Per-feature, archived |
| `adr/` | Architectural decisions with rationale | Developers, AI agents | Immutable (supersede, don't delete) |
| `product/` | Product positioning, scope, evaluation | Stakeholders, marketing | Updated per release |
| `client/` | How to use this API/service | External integrators, AI agents | Living docs |
| `marketing/` | External-facing materials | Marketing, sales | Updated per campaign |
| `architecture/` | Technical reference | Developers, AI agents | Updated on arch changes |
| `guides/` | Practical how-to | Developers, new team members | Living docs |
| `research/` | Exploratory research | Internal team | Snapshot (date-prefixed) |
| `reports/` | Milestone completion reports | Stakeholders, internal | Snapshot (immutable) |
| `.artifacts/` | Temp operational files | CI/CD, monitoring | Ephemeral (.gitignored) |

## What Does NOT Go in docs/

| Content | Where It Goes | Why |
| --- | --- | --- |
| JSON operator registries | `src/registry/` or `data/` | Data, not documentation |
| JSON Schema definitions | `api/schemas/` | Part of API contract |
| OpenAPI specs | `api/openapi.yaml` | Part of API contract |
| Test fixtures | `tests/fixtures/` | Part of test suite |
| Operational JSON logs | `docs/.artifacts/` | Ephemeral, gitignored |
| PowerShell/Python scripts | `scripts/` or `tools/` | Code, not documentation |
| PNG mockups | `docs/superpowers/specs/` (inline) or `docs/architecture/` | Alongside relevant docs |

## Pre-Write Checklist (SSOT boundary)

> Promoted из cross-repo practice-harvest, PR #293 · lineages POS, rejuve, crypto-regime-spike · recurrence 3.

Before creating **or moving** any file, answer three questions — only then proceed:

1. **What artifact class is this?** — source / generated / ephemeral.
2. **Does a canonical location already exist?** — SSOT boundary check (don't duplicate).
3. **Does the operator need to approve this write?**

Generated output must never be placed where source files live (see
[`generated-artifact-ssot`](./generated-artifact-ssot.md)). This checklist gates the
"What Does NOT Go in docs/" table above at write time.

## docs/README.md Template

Every repo's `docs/README.md` must follow this structure. **Include only sections that actually exist** — omit rows for directories the repo doesn't have. The template below shows all possible rows; the scaffolding step of `/h2t-core:scaffold-project` generates only the applicable subset based on `projects.yaml` flags and repo reality.

```markdown
# {Repo Name} Documentation

## Overview
One-paragraph description of this repository.

## Quick Links

<!-- Required core (always present) -->
| Section | Description |
|---------|-------------|
| [Specs & Plans](superpowers/) | Design specs and implementation plans |
| [ADRs](adr/) | Architectural decisions |
| [Reports](reports/) | Milestone reports |

<!-- Conditional (include only if directory exists) -->
| [Product](product/) | Positioning, scope, evaluation |
| [Client Docs](client/) | Integration guide, API reference |
| [Architecture](architecture/) | Technical design reference |
| [Guides](guides/) | How-to guides |
| [Research](research/) | Research documents |
| [Marketing](marketing/) | External-facing materials |
```

# Package architecture

Весь исполняемый код — в одном пакете со своим Python и закреплёнными зависимостями.
Плагины несут тексты, данные-ресурсы и обёртку хуков. **На машине всегда ровно одна
версия пака**: плагины и CLI равны, при расхождении h2t не работает в смеси, а называет
одну команду, которая сводит машину к одной версии.

Версия 4: окно совместимости N/N−1 заменено точным равенством после трёх раундов
adversarial-ревью Codex (журнал в §13). Все четыре P1 третьего раунда были механизмами
поддержки окна.

Первая из четырёх подсистем переработки (§11). Связи: #541 (трекер установки),
[спека wizard'а](2026-10-14-setup-wizard.md).

## 1. Проблема — что измерено

Цель — пак готов к работе у незнакомого человека без помощи автора: репозиторий
публичный. Сейчас им с трудом пользуется и сам автор. Инвентарь 2026-10-16 (субагент,
только чтение, `file:line`; четыре пункта перепроверены основной сессией):

- **Код в двух-трёх копиях.** Общая библиотека: `lib/`, ручная копия
  `plugins/h2t-core/lib/` и замороженная при сборке `h2t_ops/_plugin_payload/`.
  Коннекторы drive, meetgeek, research написаны дважды (~5100 строк на обе версии). Поиск
  файла секретов — в 6–7 местах. Установка и диагностика — в трёх местах.
- **Два канала исполнения одного кода.** Девять точек входа CLI — загрузчики скриптов
  плагина через лестницу из пяти путей (`plugin_entrypoints.py:1-22`). В кэше h2t-core
  3.2.61 — 55 файлов `.py` без Python и зависимостей: отсюда резолвер, заглушка Store,
  `uv run` за 0,9 с (D9), `jq` (D1).
- **Каналы обновляются независимо и расходятся молча.** Плагин — `/plugin marketplace
  update`, CLI — `uv tool install`. На машине автора: плагин 3.2.61, CLI 0.2.1. Каждый
  мерж в main сразу уходит всем, кто следит за marketplace: выпуска как события нет.
- **Личное автора в поставке.** ID базы задач Notion (`notion/commands.py:65`),
  `Asia/Jerusalem` в пяти местах, `Projects/DOR|Projects/newsengine`
  (`detect_project.py:35`). Идентификаторы, не секреты, но поведение у другого человека
  неверное.
- **Старые версии плагинов копятся.** Claude Code их не удаляет: семь версий h2t-core на
  машине автора.

## 2. Цель и критерии успеха

1. **Одна реализация** общей библиотеки, каждого коннектора, поиска секретов, doctor.
2. **Ноль runtime-Python в выпускаемых плагинах**; allowlist постоянных файлов:
   `hooks/run`. Ratchet по выпускаемым артефактам.
3. **Одна версия на машине.** После `h2t-setup sync <ver>` все плагины во всех
   найденных харнессах и CLI имеют версию `<ver>`. Тест на изолированных конфигах обоих
   харнессов.
4. **Расхождение никогда не молчит и никогда не шумит:** при любой смеси версий —
   одна строка на `SessionStart` с точной командой; на остальных событиях хуки h2t не
   работают и не печатают ничего. Скилл в любом харнессе первой командой видит
   расхождение и показывает ту же команду.
5. **`sync` сходится из любого состояния:** нет CLI, старый CLI, CLI новее плагинов,
   прерванная установка, разные версии в разных харнессах. Повторный запуск после сбоя
   доводит до цели. Тест вводит сбой после каждого шага.
6. **Детерминированная установка:** для фиксированной тройки «ОС, архитектура, extras»
   две установки одной версии дают один Python (точная версия, uv-managed) и один набор
   пакетов — сравнение через python окружения инструмента.
7. **Бюджеты по событиям** (тёплый запуск, p95, 20 прогонов, macOS и Windows):

   | Событие | Бюджет | Python |
   |---|---|---|
   | `UserPromptSubmit`, обычное сообщение | 50 мс | не запускается |
   | `UserPromptSubmit`, слэш-команда session-скилла | 3 с | gather |
   | `Stop` (оба хука) | 300 мс macOS / 600 мс Windows — уточняется пробой §10 | да |
   | `PostToolUse` | 150 мс | только если хуку есть что делать |
   | `SessionStart` | 1 с | да |

8. **Ожидаемый вывод** каждого хука на каждом событии записан и сверяется тестом.
9. **Литералы автора не прибавляются**; до нуля их доводит подсистема 2.

## 3. Принятые решения

| Вопрос | Решение | Отвергнуто |
|---|---|---|
| Где код | **A**: весь Python в пакете | B как общий подход — 0,9 с на Stop-хук на Windows (D9); допустим для отдельного инструмента только по замеру. C — два канала остаются |
| Совместимость | **Точное равенство** версий плагинов и CLI; расхождение → одна команда `sync` | окно N/N−1: правила устаревания, снимки интерфейса, запрет пропуска выпусков, одностороннее окно протокола — четыре P1 раунда 3 |
| Выпуск | **`marketplace.json` на main — указатель выпуска**: каждый плагин — источник `git-subdir` с `ref` = тег и `sha` = коммит тега (§7.1). Меняется только скриптом выпуска | закрепление всего marketplace на `#<тег>`: сдвиг тега — только `remove` → `add`, а `remove` удаляет плагины (проба 2026-10-16) |
| CLI | **wheel выпуска** из GitHub Release; Python точной версии uv-managed; constraints из `uv.lock` | установка из исходников: нужна сборка, `hatchling` и его цепочка, git |
| Разработка | на main, без выпуска пользователи её не видят; автор работает с плагинами из чекаута | каждый мерж сразу у всех — как сейчас |
| Имя дистрибутива | остаётся `h2t-ops`; граница в `CLAUDE.md`: `h2t-ops` — весь пак | переименование: замена сносит рабочую установку |
| Старые версии плагинов | `sync` хранит две последние на плагин | не чистить; чистить всё, кроме текущей |
| Интерфейс | команды на PATH с `--json` | MCP-сервер |

## 5. Что где лежит

```text
h2t_ops/                       пакет — единственное место исполняемого кода
  core/         пути, секреты, конфиг, чтение JSON, ошибки, конверт ответа
  lifecycle/    gather, handoff, activity, eval
  hooks/        по модулю на хук
  connectors/   по одной реализации на коннектор
  setup/        wizard, sync, update
  tools/        docs-lint, drawio, сборщик creative
  resources/    данные инструментов (шаблоны creative, defaults drawio, known_secrets),
                importlib.resources
  cli.py        точки входа

plugins/<name>/
  skills/<skill>/SKILL.md, references/*.md
  hooks/hooks.json             "command": "bash \"${CLAUDE_PLUGIN_ROOT}/hooks/run\" <hook>"
  hooks/run                    обёртка, §6.1
  release.json                 {"version": "4.1.0"} — пишет скрипт выпуска
```

Ресурсы, которые инструмент ищет рядом с собой (`assembler.py:12`, drawio
`config/defaults.yaml`), переезжают в `h2t_ops/resources/`. Проверка — wheel вне
репозитория и вне кэша плагинов (§9).

## 6. Контракты

### 6.1 Обёртка `hooks/run`

Только bash и чтение двух файлов — без запуска Python, без пробы, без кэша.

1. **Предфильтр** `UserPromptSubmit`: есть ли слэш-команда session-скилла. Нет — exit 0.
2. **Сравнить** `version` из `${CLAUDE_PLUGIN_ROOT}/release.json` с `version` из
   `~/.h2t/run/install.json` (§6.4).
3. **Действовать:**

   | Состояние | Действие |
   |---|---|
   | равны | `exec <entrypoints.h2t-hook из install.json> <name>` |
   | `install.json` с `editable` (чекаут разработчика) | то же, сравнение пропущено |
   | `install.json` нет | уведомление «CLI не установлен» |
   | плагин новее CLI | уведомление `h2t-setup sync <версия плагина>` |
   | плагин старше CLI | уведомление «плагины этого харнесса отстали» и та же команда с версией CLI |
   | `h2t-hook` вышел с кодом не 0 и не 2 | вывод отбрасывается, строка в `~/.h2t/logs/hooks.jsonl`; на `SessionStart` — уведомление «CLI неисправен» и команда `sync` |

4. **Уведомление** — только на `SessionStart`, каналом `systemMessage`, один раз на
   `session_id` (метка создаётся `mkdir`, атомарно). Каталог недоступен на запись —
   уведомление на каждом `SessionStart`, включая resume и compaction. JSON — готовый
   литерал в обёртке.

Команда в уведомлении работает без установленного CLI:

```text
uvx --python <python выпуска> --managed-python --from "<wheel выпуска>" h2t-setup sync <ver>
```

Литерал собирает скрипт выпуска; обёртка подставляет только `<ver>`. Нет `uv` — строка
установки `uv` для платформы.

Код 2 у `h2t-hook` — намеренная блокировка действия; обёртка передаёт его как есть.

### 6.2 Обработчик `h2t-hook <name>`

- читает stdin байтами и декодирует явно (`errors="replace"`);
- выбирает канал по событию одним эмиттером для всех путей выхода;
- при исключении — одна строка `h2t hook <name> failed: <класс>`, подробности в
  `~/.h2t/logs/hooks.jsonl`;
- модуль хука — чистая функция `handle(event: dict) -> Reply`.

### 6.3 Скиллы

- Первая команда каждого h2t-скилла: `h2t-ops version --expect <ver> --json`. `<ver>` —
  литерал, который ставит скрипт выпуска. Не равно, команды нет, CLI старый (не знает
  `version`) — скилл показывает команду `sync` из `hint`, а если CLI не ответил вовсе —
  литерал команды `uvx … sync`, тоже вписанный выпуском. Эта же проверка ловит
  «PATH харнесса ведёт к другой установке»: чужой CLI отвечает другой версией.
- Дальше `SKILL.md` вызывает только команды CLI, всегда с `--json`. Конверт и коды
  выхода коннекторов распространяются на все команды; в каждой ошибке — `hint` с точной
  следующей командой.
- Тест: каждая команда и флаг из `SKILL.md` есть в парсере CLI **той же версии** — окна
  нет, сравнивать с прошлым выпуском не нужно.

### 6.4 `~/.h2t/run/install.json`

Единственный источник «какая версия CLI стоит и где». Пишет только `h2t-setup`
(`sync`, `update`, `dev-sync`), атомарно.

```json
{
  "version": "4.1.0",
  "generation": "<uuid каждой записи>",
  "tool_root": "<каталог инструмента uv>",
  "entrypoints": {"h2t-hook": "<абсолютный путь>", "h2t-gather": "<…>"},
  "editable": null,
  "user_options": {"extras": ["ocr"], "with": []}
}
```

Пути берутся из `uv tool dir` и `uv-receipt.toml` в момент установки — окружение
установщика заведомо совпадает с окружением uv. Нет `install.json`, но есть старая
установка — `sync` берёт `user_options` из её receipt. `doctor` сравнивает
`entrypoints` с `command -v` в PATH харнесса и называет расхождение.

## 7. Выпуск и синхронизация

### 7.1 Выпуск

Скрипт выпуска на коммите выпуска:
1. ставит `<ver>` в `pyproject.toml`, все `plugin.json`, все `release.json`, литералы
   `--expect` и команды `sync` в `SKILL.md` и `hooks/run`;
2. экспортирует `constraints.txt`: `uv export --frozen --no-dev --all-extras
   --no-emit-project --no-hashes`;
3. пишет точную версию Python выпуска (например `3.12.11`) в `release.json` пакета;
4. один `CHANGELOG.md`; тег `v<ver>`.

CI на тег собирает wheel и прикладывает к GitHub Release вместе с `constraints.txt`.
Только после этого второй коммит на main сдвигает указатель — `marketplace.json`:

```json
{"name": "h2t-core",
 "source": {"source": "git-subdir",
            "url": "https://github.com/lichtpfad/h2t-skills.git",
            "path": "plugins/h2t-core", "ref": "v4.1.0", "sha": "<40 знаков>"}}
```

Проба 2026-10-16: плагин из `git-subdir`, закреплённого на `v2.15.0`, встал версией
3.2.3; после смены закрепления `plugin update` поднял его до 3.2.62 без `remove`.
Сокращение `owner/repo` в `url` ушло в SSH и упало — нужен полный HTTPS-адрес.
Документация: обновление приходит, только если меняется версия в `plugin.json`; при
одной версии на выпуск она меняется всегда.

Порядок «тег и wheel → указатель» гарантирует, что ни один пользователь не получит
плагины, для которых ещё нет CLI.

### 7.2 Первая установка

Человеку или агенту нужна одна команда — та же, что в уведомлении:

```bash
uvx --python <python выпуска> --managed-python --from "<wheel выпуска>" h2t-setup sync <ver>
```

Она ставит CLI и плагины во все найденные харнессы (§7.3). README и wizard дают её с
версией последнего выпуска.

### 7.3 `h2t-setup sync <ver>` — свести машину к одной версии

Запускается всегда через `uvx` с wheel целевой версии: исполнитель не живёт в
окружении, которое заменяет.

1. **Цель:** `<ver>`. Без аргумента — версия, на которую указывает marketplace.
2. **Снимок** в `~/.h2t/run/rollback/<время>/`: `install.json`, `uv-receipt.toml`,
   версии плагинов, scope и состояние enabled/disabled в каждом харнессе.
3. **CLI:** если версия CLI ≠ `<ver>` — `uv tool install --reinstall --python <python
   выпуска> --managed-python -c <constraints выпуска> "h2t-ops[<extras>] @ <wheel
   выпуска>"`; extras и `--with` — из `user_options`. Запись `install.json`.
4. **Плагины** в каждом найденном харнессе, где версия ≠ `<ver>`:
   - Claude Code: `claude plugin marketplace update lichtpfad` → `claude plugin update
     <плагин>@lichtpfad` для каждого установленного; scope и enabled — из снимка;
   - Codex: команды обновления — проба §10.
5. **Чистка кэша** плагинов: две последние версии на плагин остаются.
6. **Проверка:** `h2t-ops version --expect <ver>`, версии плагинов в каждом харнессе.
7. **Отчёт:** что приведено к `<ver>`; что не удалось и команда повтора — та же `sync`;
   открытым сессиям нужен `/reload-plugins` или новая сессия.

Сходимость: каждый шаг сравнивает текущее с целью и пропускает совпавшее. Повтор после
любого сбоя продолжает с несовпавшего. Сбой на шаге 3 при разрешении зависимостей
оставляет прежний CLI рабочим (проба 2026-10-16); прерывание посреди замены — проба §10,
восстановление — та же `sync`, работающая из `uvx`, а не из повреждённого окружения.

`h2t-setup update` = `sync` без аргумента, с показом «было → станет» и CHANGELOG и
вопросом «да?» до шага 3.

### 7.4 Чекаут разработчика

Плагины автор грузит из чекаута (`claude --plugin-dir plugins/<name>`;
`scripts/claude-dev.ps1`). `h2t-setup dev-sync` ставит editable CLI с constraints из
чекаута и `user_options` из `install.json`, пишет `install.json` с `editable`; Git не
трогает. С `editable` обёртка не сравнивает версии (§6.1): в чекауте они меняются без
выпуска. `sync` и `update` чекаут не трогают и сообщают о нём.

## 8. Миграция

Пользователи получают только выпуски, поэтому промежуточные коммиты main не обязаны быть
совместимы с установками. Миграция — это не последовательность совместимых выпусков, а
одна заморозка и один переход.

| # | Шаг | Пользователи |
|---|---|---|
| R0 | **Заморозка.** Тег на текущем main; `marketplace.json` переводится на `git-subdir`, закреплённый на этот тег. Это первый и единственный коммит, который пользователи получат до 4.0.0 | получают то же содержимое, что у них есть; дальнейшие мержи в main их больше не достигают |
| D1 | **Карта и сторожа:** таблица каждого исполняемого файла (потребители, назначение), ratchet по выпускаемым артефактам; фиксация порядка поиска секретов, fixtures с конфликтом ключей | — |
| D2 | **Пакет:** `core/`, `lifecycle/`, `hooks/`, `tools/`, `resources/`, `setup/` (`sync`, `update`, `dev-sync`), `h2t-ops version`. Точки входа зовут пакет. Порядок секретов — прежний | — |
| D3 | **Плагины:** `hooks/run`, `release.json`; скиллы на команды CLI с первой проверкой версии; удаление `hooks-handlers/`, `scripts/`, `lib/`, `_plugin_payload`, лестницы путей, `resolve-h2t-python.sh`, `setup.sh`, корневого `hooks/hooks.json` | — |
| D4 | **Выпуск:** скрипт выпуска, CI сборки wheel на тег, тесты §9 | — |
| R1 | **Выпуск 4.0.0** по §7.1 | плагины 4.0.0 при старом CLI → уведомление с командой `sync`; `sync` ставит CLI 4.0.0 |

Автор во время D1–D4 работает из чекаута (§7.4): ветка разработки не мешает его
ежедневным сессиям, пока они на замороженном выпуске.

Ни один шаг не меняет данных в `~/.h2t`, `~/.dor`, `~/.config`. Порядок поиска
секретов сохраняется; менять его — подсистема 2.

Установка Лидии закреплена на `94e038e` и не меняется, пока она не обновится сама.

## 9. Тестирование

Каждый новый тест сначала видим красным.

1. **Швы скиллов:** команды и флаги из `SKILL.md` есть в парсере CLI той же версии;
   коннекторы — контрактные сценарии на подделке API.
2. **Швы хуков:** записи `hooks.json` ↔ модули `h2t_ops/hooks/`.

# Package architecture

Весь исполняемый код — в одном пакете со своим Python и закреплёнными зависимостями.
Плагины несут тексты, данные-ресурсы и обёртку хуков. Выпуск — один тег, на который
закреплены оба канала. Поддерживается окно «текущий выпуск и один назад»; внутри окна
любая смесь версий работает, за окном — диагностируемый отказ с точной командой.

Версия 3: после двух раундов adversarial-ревью Codex (журнал в §14).

Первая из четырёх подсистем переработки (§12). Связи: #541 (трекер установки),
[спека wizard'а](2026-10-14-setup-wizard.md).

## 1. Проблема — что измерено

Цель — пак готов к работе у незнакомого человека без помощи автора: репозиторий
публичный. Сейчас им с трудом пользуется и сам автор. Инвентарь 2026-10-16 (субагент,
только чтение, `file:line`; четыре пункта перепроверены основной сессией):

- **Код в двух-трёх копиях.** Общая библиотека: `lib/`, ручная копия
  `plugins/h2t-core/lib/` (совпадение держит только `test_vendored_lib_parity.py`) и
  замороженная при сборке `h2t_ops/_plugin_payload/`. Коннекторы drive, meetgeek, research
  написаны дважды (~5100 строк на обе версии). Поиск файла секретов — в 6–7 местах.
  Установка и диагностика — в трёх: `setup_h2t.py` (836 строк), `h2t-ops doctor` (всегда
  exit 0), скилл; плюс устаревший `setup.sh`.
- **Два канала исполнения одного кода.** Девять точек входа CLI — загрузчики скриптов
  плагина через лестницу из пяти путей (`plugin_entrypoints.py:1-22`). Из 26 `SKILL.md`
  12 падают без CLI, 8 запускают свои `scripts/*.py`. В кэше h2t-core 3.2.61 — 55 файлов
  `.py` без Python и зависимостей: отсюда резолвер, заглушка Store, `uv run` за 0,9 с
  (D9), `jq` (D1).
- **Личное автора в поставке.** ID базы задач Notion в коде коннектора
  (`notion/commands.py:65`) и в daily brief; `Asia/Jerusalem` в пяти местах; регулярка
  `Projects/DOR|Projects/newsengine` (`detect_project.py:35`). Это идентификаторы, не
  секреты: без токена владельца по ним ничего не прочитать, но поведение у другого
  человека неверное.
- **Версии ничего не говорят.** Пакет всегда `0.2.1` (D6). Старый `h2t-hook --version`
  ищет обработчик с именем `--version` и выходит с кодом 5 (проверено 2026-10-16).
- **Старые версии плагинов копятся.** Claude Code их не удаляет: на машине автора было
  семь версий h2t-core (3.2.47–3.2.61) и восемь h2t-ops (проверено 2026-10-16).

## 2. Цель и критерии успеха

Каждый критерий — тест или измерение с порогом.

1. **Одна реализация.** Общая библиотека, каждый коннектор, поиск секретов, doctor — по
   одному месту.
2. **Ноль runtime-Python в выпускаемых плагинах.** Разрешено только то, что в allowlist
   постоянных файлов: `hooks/run`. Ratchet по выпускаемым артефактам, не по дереву.
3. **Детерминированная установка.** Для фиксированной тройки «ОС, архитектура, extras»
   две установки одного тега дают одинаковую версию Python (uv-managed) и одинаковый
   набор пакетов: `uv pip freeze --python <python окружения инструмента>`.
4. **Бюджеты по событиям** (тёплый запуск, p95, 20 прогонов, macOS и Windows):

   | Событие | Бюджет | Python |
   |---|---|---|
   | `UserPromptSubmit`, обычное сообщение | 50 мс | не запускается |
   | `UserPromptSubmit`, слэш-команда session-скилла | 3 с | gather |
   | `Stop` (оба хука вместе) | 300 мс macOS / 600 мс Windows — уточняется пробой §11 | да |
   | `PostToolUse` | 150 мс | только если хуку есть что делать |
   | `SessionStart` | 1 с | да |

5. **Ожидаемый вывод.** Для каждого хука и события записан ожидаемый вывод: gather
   возвращает брифинг, guard без нарушения — пустой ответ. Тест сверяет вывод.
6. **Окно совместимости.** Внутри окна N/N−1 все четыре комбинации плагина и CLI
   работают функционально: session-start даёт брифинг, handoff пишет запись, скиллы
   находят свои команды. За окном — сообщение с точной командой обновления, и ничего
   больше.
7. **Обновление восстанавливаемо.** Сбой на любом шаге `update` оставляет установку в
   окне совместимости. Тест вводит сбой после каждого шага.
8. **Литералы автора не прибавляются.** Ratchet не растёт; до нуля их доводит подсистема
   2, у которой есть куда их переложить (§12).

## 3. Принятые решения

| Вопрос | Решение | Отвергнуто |
|---|---|---|
| Где код | **A**: весь Python в пакете | B как общий подход — 0,9 с на Stop-хук на Windows (D9); допустим для отдельного редкого инструмента только по замеру. C как конечное состояние — два канала остаются |
| Как переезжать | **Сначала добавить, потом удалить**: старое остаётся на прежних путях, пока новое не проработало выпуск | удалить и перенести одним шагом |
| Поддержка старого | **Окно N/N−1** | бессрочная поддержка старого CLI: вторая копия кода в плагине навсегда |
| Совместимость | два контракта: **протокол хуков** и **снимок интерфейса CLI** (§6.3) | сравнение номеров версий |
| Выпуск | один тег на оба канала + `release.json` на теге (§7.1) | CLI из тега, плагины с main |
| Зависимости | Python 3.12 uv-managed, constraints и build-constraints из `uv.lock` | диапазоны `pyproject.toml` |
| Имя дистрибутива | остаётся `h2t-ops`; граница в `CLAUDE.md`: `h2t-ops` — весь пак | переименование: замена сносит рабочую установку |
| Старые версии плагинов | `update` хранит две последние на плагин, остальные удаляет | не чистить (копятся годами); чистить всё, кроме текущей (ломает открытые сессии) |
| Интерфейс | команды на PATH с `--json` | MCP-сервер |

## 5. Что где лежит

```text
h2t_ops/                       пакет — единственное место исполняемого кода
  core/         пути, секреты, конфиг, чтение JSON, ошибки, конверт ответа
  lifecycle/    gather, handoff, activity, eval          (из lib/)
  hooks/        по модулю на хук
  connectors/   по одной реализации на коннектор
  setup/        wizard, update
  tools/        docs-lint, drawio, сборщик creative      (из scripts/ плагинов)
  resources/    данные инструментов (шаблоны creative, defaults drawio, known_secrets),
                читаются через importlib.resources
  cli.py        точки входа

plugins/<name>/                плагин
  skills/<skill>/SKILL.md, references/*.md
  hooks/hooks.json             "command": "bash \"${CLAUDE_PLUGIN_ROOT}/hooks/run\" <hook>"
  hooks/run                    обёртка, §6.1 — единственный постоянный исполняемый файл
  hooks/interface.json         снимок интерфейса CLI, который нужен скиллам (§6.3)
  hooks-handlers/              старые обработчики НА ПРЕЖНИХ ПУТЯХ — только до C1 (§8)
```

Ресурсы, которые инструмент ищет рядом с собой (`assembler.py:12`,
`Path(__file__).parent / "base"`; drawio — `config/defaults.yaml`), переезжают в
`h2t_ops/resources/`. Проверка — wheel вне репозитория и вне кэша плагинов (§9.7).

## 6. Контракты

### 6.1 Обёртка `hooks/run`

Порядок действий — от дешёвого к дорогому:

1. **Предфильтр.** Для `UserPromptSubmit` — bash-решение «есть ли слэш-команда
   session-скилла» (как в `gather-on-prompt` после #543). Нет — exit 0, ничего больше.
2. **Найти CLI** по `~/.h2t/run/install.json` (§6.4): абсолютный путь `h2t-hook`. Файла
   нет — `command -v h2t-hook`.
3. **Определить состояние** по кэшу `~/.h2t/run/probe.json`, ключ — идентичность
   установки из `install.json` (§6.4). Нет записи или ключ не совпал — проба
   `h2t-hook --protocol` с таймаутом 2 с, stdout и stderr перехвачены, stdin события
   сохранён для обработчика. Запись кэша атомарная (временный файл + rename). Каталог
   недоступен на запись — работает без кэша.
4. **Действовать по таблице исходов:**

   | Исход пробы | Состояние | Действие |
   |---|---|---|
   | `h2t-hook-protocol P`, P в окне плагина | годен | `h2t-hook <name>` |
   | `h2t-hook-protocol P`, P вне окна | устарел или новее окна | обработчик из `hooks-handlers/`, пока он есть (до C1); после C1 — уведомление |
   | код 5 и текст `Plugin entrypoint script not found` | CLI до введения протокола | то же |
   | CLI не найден | нет CLI | то же |
   | таймаут, traceback, код ≠ 0 без признаков выше, `permission denied` | неисправен | уведомление «CLI неисправен → `h2t-ops doctor`»; без повторной пробы до смены идентичности |

5. **Уведомление** — только на `SessionStart`, каналом `systemMessage` (его видит
   человек), один раз на `session_id` из payload: метка `~/.h2t/run/notified/<session_id>`
   создаётся атомарно (`mkdir`). Каталог недоступен — уведомление на каждом
   `SessionStart`, включая resume и compaction. На остальных событиях — exit 0 без
   вывода. JSON уведомления — готовый литерал в обёртке: Python-эмиттер на этом пути
   недоступен.

Текст уведомления содержит команду, работающую без CLI (§7.2):

```text
h2t: CLI не установлен. Установить: uvx --python 3.12 --managed-python -c "<constraints тега>" --from "h2t-ops @ <архив тега>" h2t-setup
```

Если нет `uv` — строка установки `uv` для платформы.

### 6.2 Обработчик `h2t-hook <name>`

- читает stdin байтами и декодирует явно (`errors="replace"`);
- выбирает канал по событию одним эмиттером для всех путей выхода;
- при исключении — одна строка `h2t hook <name> failed: <класс> → h2t-ops doctor`,
  подробности в `~/.h2t/logs/hooks.jsonl`;
- ненулевой код — только при намеренной блокировке действия;
- модуль хука — чистая функция `handle(event: dict) -> Reply`.

### 6.3 Совместимость: протокол и интерфейс

Два независимых контракта, оба проверяются тестами.

- **Протокол хуков** — целое число в `h2t-hook --protocol`. Меняется только при смене
  формата обмена обёртки и обработчика. Плагин объявляет окно `[P−1, P]`.
- **Интерфейс CLI** — снимок `cli-interface.json`, генерируемый из парсера: команды,
  флаги, версия JSON-схемы ответа каждой команды. Хранится на каждом теге.
  - **Правило добавления:** скиллы выпуска N используют только интерфейс, который был в
    CLI N−1. Новая команда или флаг появляется в CLI на выпуск раньше, чем ею начинает
    пользоваться скилл. Тест: каждый вызов в `SKILL.md` выпуска N есть в снимке N−1.
  - **Правило удаления:** команда или флаг помечается устаревшим на один выпуск
    (работает, печатает предупреждение) и удаляется в следующем.
  - Отсюда смесь «плагин N + CLI N−1» работоспособна по построению, а «плагин N−1 +
    CLI N» — потому что CLI N ещё держит устаревшее.
  - `hooks/interface.json` плагина — подмножество снимка, которое нужно его скиллам.
    `h2t-ops doctor --quick --requires hooks/interface.json` сверяет его с установленным
    CLI; так проверка работает и в Codex, где хуков нет.

### 6.4 Обнаружение установки — `~/.h2t/run/install.json`

Единый источник для обёртки хуков, `doctor` и скиллов. Пишут его `h2t-setup install`,
`update` и `dev-sync`; ни один другой код его не пишет.

```json
{
  "tool_root": "<каталог инструмента uv, h2t-ops/>",
  "entrypoints": {"h2t-hook": "<абсолютный путь>", "h2t-gather": "<…>", "…": "…"},
  "identity": "<sha256 содержимого uv-receipt.toml>",
  "editable": null,
  "release": "v4.0.0",
  "user_options": {"extras": ["ocr"], "with": []}
}
```

- `tool_root` и пути берутся из `uv tool dir` и `uv-receipt.toml` в момент установки,
  когда окружение установщика заведомо совпадает с окружением uv, — а не угадываются
  позже по `UV_TOOL_DIR`, которого у харнесса может не быть.
- **editable:** `{"path": "<чекаут>"}`. Код меняется без переустановки, поэтому для
  editable кэш пробы не используется — проба при каждом `SessionStart`.
- `doctor` сравнивает `entrypoints` с тем, что находит `command -v` в PATH харнесса, и
  сообщает о расхождении: хук зовёт одну установку, скилл — другую.

## 7. Выпуск, установка, обновление

### 7.1 Выпуск

Тег `v<ver>` на коммите, где одновременно:
- `pyproject.toml`, все `plugin.json`, `marketplace.json` несут `<ver>`;
- `release.json`:

  ```json
  {"version": "4.0.0", "protocol": 1, "python": "3.12",
   "constraints": "constraints.txt", "build_constraints": "build-constraints.txt",
   "interface": "cli-interface.json", "previous": "3.x"}
  ```
- `constraints.txt` — `uv export --frozen --no-dev --all-extras --no-emit-project
  --no-hashes`: все extras закреплены, сам проект не включён;
- `build-constraints.txt` — закреплённый `hatchling` (сборка проекта);
- `cli-interface.json` — снимок §6.3;
- один `CHANGELOG.md`.

Между мержем и тегом пользователей нет: README и wizard ставят только из тега.

### 7.2 Установка

Источник выпуска — архив тега: `https://github.com/lichtpfad/h2t-skills/archive/refs/tags/v<ver>.zip`.
Проба 2026-10-16: uv ставит из архива GitHub без git в PATH, `-c` по URL принимается.

```bash
uv tool install --python 3.12 --managed-python \
  -c "<constraints.txt тега>" -b "<build-constraints.txt тега>" \
  "h2t-ops[<extras>] @ <архив тега>"
claude plugin marketplace add "lichtpfad/h2t-skills#v<ver>" --json
```

Бутстрап, когда CLI ещё нет, — `uvx` с теми же `--python`, `--managed-python`, `-c`, `-b`
и источником (§6.1). Работает из любого каталога: проект пользователя не участвует.

### 7.3 Обновление — `h2t-setup update`

**Помощник обновления не живёт в заменяемом окружении:** `update` перезапускает себя
через `uvx` со спецификацией нового выпуска и дальше работает оттуда.

1. Читает `release.json` нового тега, показывает «было → станет» и изменения из
   CHANGELOG. Ждёт «да».
2. **Снимок состояния** в `~/.h2t/run/rollback/<время>/`: `install.json`, копия
   `uv-receipt.toml`, закреплённые ref marketplace и версии плагинов в каждом харнессе.
3. **Итоговая спецификация** = спецификация выпуска из `release.json` (источник,
   Python, constraints, build-constraints) + пользовательские опции из `install.json`
   (extras, `--with`). Старые constraints не переносятся.
4. **Пробная установка** итоговой спецификации во временный `UV_TOOL_DIR` /
   `UV_TOOL_BIN_DIR`. Сбой — стоп, ничего не тронуто. Проба 2026-10-16: упавшее
   разрешение зависимостей при `--reinstall` оставляет прежнюю установку рабочей; сбой
   посреди замены — проба §11.
5. **CLI первым:** установка поверх той же итоговой спецификацией, `h2t-hook --protocol`,
   запись `install.json`. Окно N/N−1 делает «новый CLI + старые плагины» рабочим
   состоянием, поэтому дальнейший сбой не требует отката CLI.
6. **Плагины в каждом харнессе по очереди.** Сбой в одном харнессе оставляет его на
   N−1 — это внутри окна; отчёт называет харнесс и команду повтора.
   - Claude Code: закреплённый тег сдвигается только `marketplace remove` → `add
     #<новый тег>` (проба 2026-10-16: повторный `add` отклоняется —
     `source doesn't match its extraKnownMarketplaces entry`). Удаляет ли `remove`
     установленные плагины — проба §11; если да, шаг переустанавливает их из снимка.
   - Codex: `codex plugin marketplace add <repo>@<тег>` — проба §11.
7. **Чистка кэша плагинов**: две последние версии на плагин остаются, остальные
   удаляются. Отчёт говорит, что сессии, открытые до двух обновлений назад, требуют
   `/reload-plugins`.
8. `verify`. Отчёт: что обновлено, что осталось на N−1 и почему, что открытым сессиям
   нужен `/reload-plugins` или новая сессия.

**Откат CLI** (если сбой на шаге 5): установка из снимка receipt; с `--offline`, если
сеть недоступна, — wheel'ы предыдущего выпуска лежат в кэше uv (проба §11).

### 7.4 Чекаут разработчика

`update` чекаут не трогает: показывает коммит, ветку, грязное ли дерево. `h2t-setup
dev-sync` переустанавливает editable-окружение с constraints из чекаута (`uv export` на
месте) и пишет `install.json` с `editable`; Git не трогает.

## 8. Миграция — сначала добавить, потом удалить

Нижняя поддерживаемая точка — последний выпуск до E1 (обозначен L). Окно на каждом шаге
— два соседних выпуска.

| # | Шаг | Почему комбинации живы |
|---|---|---|

## 9. Тестирование

Каждый новый тест сначала видим красным.

1. **Швы скиллов:** каждая команда и флаг из `SKILL.md` выпуска N есть в
   `cli-interface.json` выпуска N−1; для коннекторов — контрактные сценарии на подделке
   API: аргументы, результат, побочные эффекты.
2. **Швы хуков:** каждая запись `hooks.json` ↔ модуль в `h2t_ops/hooks/`.
3. **Ожидаемый вывод и бюджеты** каждого хука на каждом событии (§2.4, §2.5), без `jq` и
   системного Python, Linux и Windows.
4. **Обёртка — все строки таблицы §6.1:** нет CLI; CLI до протокола (**настоящая сборка
   выпуска L**, не подделка); протокол вне окна; неисправный CLI (traceback, таймаут,
   permission denied); каталог `~/.h2t/run` недоступен; повторный `SessionStart` в той же
   сессии.
5. **Окно совместимости:** четыре комбинации N/N−1 функционально, на настоящих сборках
   двух выпусков (§2.6).
6. **Старые данные:** fixtures сессий, спула, секретов в старых форматах и местах.
7. **Wheel вне репозитория:** установка в пустой HOME (на Windows ещё `USERPROFILE`,
   `APPDATA`, каталоги uv), без чекаута и кэша плагинов — инструменты находят ресурсы.
8. **Детерминированность** (§2.3): две установки тега, сравнение через python окружения
   инструмента, в фиксированной тройке ОС/архитектура/extras.
9. **Сбой обновления:** сбой после каждого шага §7.3 → установка в окне (§2.7);
   base → `[ocr]` → update → OCR на месте.
10. **Ratchet** по выпускаемым артефактам и по литералам автора.
11. **Нет рекурсии:** ни один скрипт плагина не вызывает команду CLI, чья точка входа
    может загрузить этот же скрипт (статическая проверка по карте E0).

Живая приёмка — матрица §4 на настоящих машинах.

## 10. Старые версии и личное на других машинах

Код автора уходит с машины пользователя двумя путями: `uv tool install` пересобирает
окружение CLI целиком, а чистка кэша (§7.3.7) удаляет плагины старше двух выпусков.
Через два обновления после выпуска, где литерал заменён настройкой (подсистема 2), его
нет на диске. Из истории публичного репозитория идентификаторы не убираются: они не
секреты. Для секретов правило другое — ротация (`.claude/rules/secrets.md`).

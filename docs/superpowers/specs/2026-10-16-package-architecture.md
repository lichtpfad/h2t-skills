# Package architecture

Весь исполняемый код — в одном пакете со своим Python и зависимостями. Плагины несут
только тексты и однострочный вызов. Одна версия на всё, выпуск — тег.

Первая из четырёх подсистем переработки (§10). Связи: #541 (трекер установки),
[спека wizard'а](2026-10-14-setup-wizard.md).

## 1. Проблема — что измерено

Цель — пак готов к работе у незнакомого человека без помощи автора: репозиторий
публичный. Сейчас им с трудом пользуется и сам автор. Инвентарь 2026-10-16 (субагент,
только чтение, `file:line`; четыре пункта перепроверены основной сессией):

- **Код в двух-трёх копиях.** Общая библиотека: `lib/`, ручная копия
  `plugins/h2t-core/lib/` (совпадение держит только `test_vendored_lib_parity.py`) и
  замороженная при сборке `h2t_ops/_plugin_payload/`. Коннекторы drive, meetgeek, research
  написаны дважды: `h2t_ops/connectors/drive/client.py` (1677 строк) «mirrors»
  `skills/drive/scripts/drive_cli.py` (531), всего ~5100 строк на обе версии. Поиск файла
  секретов реализован заново в 6–7 местах. Установка и диагностика — в трёх:
  `setup_h2t.py` (836 строк), `h2t-ops doctor` (всегда exit 0), скилл; плюс устаревший
  `setup.sh`.
- **Два канала исполнения одного кода.** Девять точек входа CLI — загрузчики скриптов
  плагина через лестницу из пяти путей (`plugin_entrypoints.py:1-22`). Из 26 `SKILL.md`
  12 падают без CLI, 8 запускают свои `scripts/*.py`, 7 не делают ни того ни другого.
  В кэше h2t-core 3.2.61 — 55 файлов `.py`, которым Claude Code не даёт ни Python, ни
  зависимостей: отсюда резолвер интерпретатора, заглушка Store, `uv run` за 0,9 с (D9),
  `jq` (D1).
- **Личное автора в поставке.** ID базы задач Notion в коде коннектора
  (`notion/commands.py:65`) и в daily brief; `Asia/Jerusalem` в пяти местах; регулярка
  `Projects/DOR|Projects/newsengine` (`detect_project.py:35`); имена машин в шаблонах.
- **Имя без одного значения.** `h2t-ops` — плагин, Python-пакет, команда и пространство
  имён скиллов. Версия пакета всегда `0.2.1`, у пяти плагинов свои пять номеров
  (D6). «h2t-ops обновлён» не говорит, что обновлено.

## 2. Цель и критерии успеха

1. В `plugins/` нет ни одного `.py`; ratchet-тест держит 0.
2. У каждой функции одна реализация: общая библиотека, каждый коннектор, поиск секретов,
   doctor.
3. Ни один хук не ищет интерпретатор: хуки исполняет окружение пакета.
4. Обычное сообщение — до 50 мс в хуках, без запуска интерпретатора, на macOS и Windows.
5. Один номер версии у пакета и всех плагинов; `--version` меняется с каждым выпуском.
6. Обновление — одна команда, доводящая до диска плагины, CLI и новые зависимости.
7. В коде пакета нет значений автора (ratchet по известным литералам).

## 3. Принятые решения

| Вопрос | Решение | Отвергнуто |
|---|---|---|
| Где код | **Подход A**: весь Python в пакете, плагины — тексты и `hooks/run` | B — плагины самодостаточны через `uv run` в скрипте: 0,9 с на вызов на Windows (замер D9), тяжёлые Google-библиотеки при первом вызове, общий код копировался бы между плагинами. C — оставить два канала и убрать дубли на месте: путаница «плагин или пакет, какая версия» остаётся |
| Как зовут хуки | `bash hooks/run <name>` → `h2t-hook <name>` | `h2t-hook` прямо в `hooks.json`: без CLI — `command not found` на каждом сообщении, как с `jq` |
| Интерфейс | команды на PATH с `--json` | MCP-сервер: отдельная установка и конфиг в каждом харнессе |
| Версии | одна на пакет и все плагины, старт `4.0.0` | пять независимых номеров |
| Выпуск | git-тег; установка из тега | установка с main |
| Имя дистрибутива | **`h2t-skills`**, как у репозитория. Команды, плагины и модуль `h2t_ops` не меняются | оставить `h2t-ops`: пакет уже содержит жизненный цикл сессий, хуки и setup, что противоречит границе «h2t-ops owns operational connectors ONLY» в `CLAUDE.md` |

## 4. Что где лежит

```text
h2t_ops/                       пакет — единственное место исполняемого кода
  core/         пути, секреты, конфиг, чтение JSON, ошибки, конверт ответа
  lifecycle/    gather, handoff, activity, eval          (из lib/)
  hooks/        по модулю на хук
  connectors/   по одной реализации на коннектор
  setup/        wizard
  tools/        docs-lint, drawio, сборщик creative      (из scripts/ плагинов)
  cli.py        точки входа

plugins/<name>/                плагин — тексты
  skills/<skill>/SKILL.md, references/*.md
  hooks/hooks.json             "command": "bash \"${CLAUDE_PLUGIN_ROOT}/hooks/run\" <hook>"
  hooks/run                    ~20 строк bash, единственный не-markdown файл
```

`hooks/run`:

1. находит `h2t-hook`: PATH, затем каталог, куда uv кладёт команды (`~/.local/bin`) —
   на Windows PATH после установки обновляется только в новом окне;
2. если не найден — одна строка «CLI не установлен → `h2t-setup`» за сессию, exit 0;
3. для событий на каждом сообщении сначала дешёвая проверка на bash (есть ли слэш-команда
   в начале), и только если хуку есть что делать — вызов `h2t-hook`.

Зависимости: базовые и extras; OCR (`rapidocr-onnxruntime`, ~250 МБ из 404 МБ окружения)
— в `h2t-skills[ocr]`.

## 5. Контракт вызовов

### Хуки

`h2t-hook` берёт на себя то, что сейчас каждый обработчик делает сам:

- читает stdin байтами и декодирует явно (`errors="replace"`): урок `400 invalid high
  surrogate`, сейчас записанный комментарием в одном `gather-on-skill`;
- выбирает канал по событию — `additionalContext` модели, `systemMessage` человеку —
  одним эмиттером для всех путей выхода, включая ранние (`.claude/rules/hooks.md`);
- при исключении — одна строка `h2t hook <name> failed: <класс> → h2t-ops doctor`,
  подробности в `~/.h2t/logs/hooks.jsonl`. Молчащий хук — сбой, а не норма;
- ненулевой код — только при намеренной блокировке действия.

Модуль хука — чистая функция `handle(event: dict) -> Reply`.

### Скиллы

`SKILL.md` вызывает только команды CLI, всегда с `--json`. Конверт и коды выхода
коннекторов (0 ok, 1 provider, 2 usage, 3 config, 4 auth, 5 not found, 6 network)
распространяются на все команды, включая gather, handoff, setup. В каждой ошибке — `hint`
с точной следующей командой: агент показывает его, а не придумывает ремонт.
`compatibility` каждого скилла называет нужную версию CLI и внешние зависимости.

## 6. Версии, выпуск, обновление

- `bump <ver>` ставит номер в `pyproject.toml`, все `plugin.json`, `marketplace.json`.
  Один `CHANGELOG.md` вместо пяти.
- Выпуск: мерж с подъёмом версии → тег `v<ver>`. Установка:
  `uv tool install "git+https://github.com/lichtpfad/h2t-skills.git@v<ver>"`.
- На `SessionStart` хук один раз сравнивает версию плагина с `h2t-hook --version`; при
  расхождении — одна строка `h2t: плагины X, CLI Y → h2t-setup update`. На каждом
  сообщении не сравнивает: это запуск Python.
- `h2t-setup update`: показывает «было → станет» и изменения из CHANGELOG; после «да» —
  `uv tool install --reinstall` из тега (ставит новые зависимости, D5), обновление
  marketplace и плагинов в каждом харнессе, чистка кэша до двух последних версий на
  плагин, `verify`. Идёт и через протокол `next`/`answer`.
- Чекаут разработчика: `--version` показывает тег, коммит и путь editable-установки;
  `update` делает `git pull` и `uv tool install --reinstall --editable <путь>` и не
  заменяет чекаут установкой из тега.

## 7. Миграция

Каждый шаг — отдельный PR; после каждого всё работает; откат — revert.

| # | Шаг | Что исчезает | Проверка |
|---|---|---|---|
| M0 | Сторожа с сегодняшними числами: `.py` в `plugins/`, литералы автора, команды из `SKILL.md` есть в парсере | — | числа только убывают |
| M1 | `h2t_ops/core/`: секреты, чтение конфигов, ошибки; все цепочки секретов зовут один модуль | 6 копий цепочки | секрет в каждом из 8 мест находит каждый коннектор |
| M2 | `lib/` → `h2t_ops/lifecycle/`; точки входа импортируют напрямую | `lib/`, `plugins/h2t-core/lib/`, `_plugin_payload`, лестница путей | gather/handoff/activity: тест по кругу «записал → прочитал» |
| M3 | хуки → `h2t_ops/hooks/` + `h2t-hook` + `hooks/run` | `hooks-handlers/*`, `resolve-h2t-python.sh` | тесты швов §8 на Linux и Windows |
| M4 | коннекторы: тест «каждый глагол скрипта есть в CLI», затем удаление скриптов | `skills/{drive,meetgeek,research}/scripts` | этот тест |
| M5 | инструменты → `h2t_ops/tools/`, тяжёлое — в extras | `scripts/` в dev, arch, creative | ratchet `.py` в `plugins/` = 0 |
| M6 | версия `4.0.0`, один CHANGELOG, тег, `h2t-setup update`, дистрибутив `h2t-skills` | `setup.sh`, корневой `hooks/hooks.json`, `h2t_ops/dev.py` | установка из тега в пустой HOME |

**Переходное состояние.** Плагины и CLI обновляются независимо. Плагин версии N требует
CLI не ниже N; пока CLI старее, `hooks/run` печатает одну строку «обнови CLI» за сессию.
CI проверяет обе комбинации (новый плагин + старый CLI, старый плагин + новый CLI): ни в
одной нет ошибки на каждом сообщении.

**Переименование дистрибутива.** Новый пакет приносит команды с теми же именами, поэтому
на машине со старой установкой `uv tool install` конфликтует. `h2t-setup update` сначала
делает `uv tool uninstall h2t-ops`. Это разовая цена для уже поставивших (машины автора,
Лидия); новые пользователи её не видят. Установка Лидии закреплена на `94e038e` и не
меняется, пока она не обновится сама.

**Данные не трогаются.** M0–M6 ничего не меняют в `~/.h2t`, `~/.dor`, `~/.config`. Пути и
секреты — подсистема 2, по правилу «записать, а не перенести» (спека wizard'а, §14).

## 8. Тестирование

Каждый новый тест сначала видим красным.

1. **Швы скиллов:** каждая команда и флаг из любого `SKILL.md` существуют в парсере CLI.
2. **Швы хуков:** каждая запись `hooks.json` имеет модуль в `h2t_ops/hooks/`, и наоборот.
3. **Хуки на платформах:** каждый хук на каждом своём событии, без `jq` и системного Python,
   на Linux и Windows — молчит при успехе, укладывается в бюджет (§2.4).
4. **Нет CLI:** подделка без `h2t-hook` — `hooks/run` печатает одну строку за сессию.
5. **Две версии:** обе комбинации старого и нового (§7).
6. **Ratchet:** `.py` в `plugins/`, литералы автора, копии цепочки секретов.
7. **Установка из тега** в пустой HOME и изолированный `CLAUDE_CONFIG_DIR`.

CI: Linux и Windows, все пути `evals.yml`.

## 9. Проверить до плана

- Можно ли закрепить плагины marketplace Claude Code на тег или ref. Если нет — плагины
  берутся с main, расхождение ловит проверка версий на `SessionStart`.
- Стоимость запуска `h2t-hook` на Windows (старт Python + импорт пакета): укладывается ли
  хук, которому есть что делать, в разумное время; импорты пакета ленивые.
- Поведение `uv tool install` при конфликте имён команд со старым `h2t-ops`: точный текст
  ошибки и код выхода, чтобы `update` различал этот случай.

## 10. Вне рамок — следующие подсистемы

1. **Эта спека** — код и доставка.
2. **Состояние и конфиг** — файл путей, одно место для секретов, личное в конфиг
   пользователя (D3, D4, D21–D23); `decision.yml`.
3. **Установка** — wizard ([спека](2026-10-14-setup-wizard.md)); ляжет на один пакет.
4. **Система пользователя** — daily brief, задачи, POS как надстройка.

## 11. Отбраковано

- «Плагин без CLI работает частично» как довод против A: 12 из 26 скиллов уже падают без
  CLI, и падают молча; A делает зависимость явной, а не создаёт её.
- Переименование модуля `h2t_ops`: большой дифф без пользы для человека — имя модуля не
  видно ни в одной команде.

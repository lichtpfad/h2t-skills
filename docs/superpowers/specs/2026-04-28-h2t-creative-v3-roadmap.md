# h2t-creative v3 — Высокоуровневый Roadmap

**Date:** 2026-04-28
**Status:** Approved
**Scope:** 4 подсистемы, детальные спеки — по одной на фазу.

---

## Контекст

h2t-creative v2 реализован: 4-слойная архитектура (base CSS → профиль → assembler.py → skills), один профиль `h2t-default`, 5 базовых компонентов, Playwright QA. v3 расширяет систему до production-уровня.

---

## Фазы

### Фаза 1 — A · Profiles (Design Systems)

**Цель:** 3–5 полноценных визуальных профилей, каждый с DESIGN.md + tokens.css + все компоненты в стиле профиля.

**Кандидаты профилей:**
- `h2t-default` — уже существует (светлый, editorial, Swiss grid)
- `h2t-dark` — тёмный HUD/тактический (ранее был в `h2t:landing`)
- `h2t-brand` — Hou2Touch brand colors
- `h2t-minimal` — ультраминимализм, максимум whitespace
- `h2t-warm` — опционально, под рассмотрение

**Зависимости:** нет → строим первым.

---

### Фаза 2 — B · Block Library

**Цель:** 10–20 переиспользуемых секций поверх базовых 5. Все блоки используют только CSS-токены → работают с любым профилем автоматически.

**Кандидаты блоков:**
- `pricing` — тарифные планы (1–3 колонки)
- `features-grid` — сетка возможностей с иконками/заголовками
- `timeline` — хронология событий
- `testimonials` — отзывы / цитаты
- `faq` — аккордеон вопрос–ответ
- `comparison-table` — таблица сравнения
- `gallery` — сетка изображений
- `stats-bar` — большие цифры / ключевые метрики
- `video-embed` — embed блок (YouTube/Vimeo)
- `team` — карточки команды
- `quote` — одиночная цитата с акцентом
- `countdown` — таймер обратного отсчёта

**Зависимости:** нужны профили (Фаза 1) для тестирования блоков в контексте.

---

### Фаза 3 — C · Content Capacity Guide

**Цель:** для каждого блока × профиля задокументировать сколько контента помещается без overflow: текст (символы), строки таблиц, количество элементов списка, колонки.

**Механизм:**
- Расширение `manifest.yaml` полем `capacity:`
- Auto-generated `capacity.md` через Playwright-измерения при разных размерах контента
- Агент читает capacity перед сборкой recipe → предупреждает если контент превышает лимиты

**Зависимости:** нужны Фаза 1 + Фаза 2.

---

### Фаза 4 — D · Self-learning Skill

**Цель:** скилл накапливает знания из прошлых запусков и использует их при следующих.

**Механизм:**
- После каждого запуска `/landing` или `/deck` — запись в knowledge-файл: что сработало, что сломалось, edge-cases
- Хранение: `~/.h2t/creative-knowledge.md` или в профиле
- Покрывает: overflow-паттерны, проблемные комбинации блок+контент, удачные recipe-структуры

**Зависимости:** наиболее полезна после A+B+C, но архитектуру можно проектировать параллельно с C.

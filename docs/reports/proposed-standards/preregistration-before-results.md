# Pre-Register Feature Set, Thresholds, and Target Labels Before Any Run

**Proposed home:** `C:/dev/docs/standards/preregistration-before-results.md` (NEW)
**Track:** technical · **Recurrence:** 1 lineage(s) · **Domain-independence:** medium

## TL;DR
Before executing any experiment, benchmark, or validation run, commit a pre-registration document that declares: the feature set, thresholds, success criteria, and (where applicable) target-label definitions such as horizon, holding period, and execution parameters. The pre-registration must be committed before any results are seen. This eliminates researcher degrees of freedom — the post-hoc temptation to adjust thresholds or feature selections after observing outcomes. Any deviation from the pre-registration must be documented as a deviation, not silently applied.

# Enforce an Internal vs Client-Facing Document Boundary

**Proposed home:** `C:/dev/docs/standards/internal-external-document-boundary.md` (NEW)
**Track:** process · **Recurrence:** 1 lineage(s) · **Domain-independence:** medium

## TL;DR
Keep analytical framework labels, hypothesis notation, founder-narrative language, and technical scoring notation out of any client-facing or published artifact. Client artifacts must be scrubbed of internal markers before publication. Maintain a clear written boundary (ideally in a doc header or template) that says which elements belong only in internal docs and which may appear in public-facing HTML or deliverables. Boundary enforcement is preventive — check at draft time, not at publish time.
